# AGENTS.md

Guidance for AI coding agents (and humans) working in this repository.

> **Status: v1 feature-complete (Waves 0–2 done).** Every MUST and SHOULD requirement has tests;
> remaining work is Wave 3 polish/hardening (see `docs/IMPLEMENTATION_PLAN.md`).

## What this app is

A self-hosted **UX card sort research tool**. A single admin creates card sort *studies* (open,
closed or hybrid), defines cards, groups, participant permissions and which participant details
to collect, then shares a link. Participants sort cards into groups on a drag-and-drop board that
auto-saves every change, and finish via a confirmation modal that freezes the board. The admin
sees every board (in progress and completed) and analyses results with a similarity matrix,
placement matrix and dendrogram.

## Key documents (read before changing behaviour)

- `docs/REQUIREMENTS.md` — what must be built, with stable requirement IDs (`STU-03`, `SAVE-01`, …)
  and acceptance criteria. **This defines "done".**
- `docs/DESIGN.md` — architecture, data model, permission matrix, API, auto-save protocol,
  analysis algorithms.
- `docs/IMPLEMENTATION_PLAN.md` — build waves, parallel workstreams, file ownership per stream,
  and the rules for sub-agents.

**Keep the docs current.** Whenever behaviour, architecture or requirements change, update
`docs/REQUIREMENTS.md` and `docs/DESIGN.md` in the same change. (When working as a parallel
stream sub-agent, report doc changes to the coordinator instead — see the plan §2.)

## Tech stack

Next.js 16 (App Router, Turbopack) · React 19 · TypeScript (strict) · SQLite (better-sqlite3) ·
Drizzle ORM · zod 4 · dnd-kit · Tailwind CSS 4 · Radix UI Dialog · iron-session · bcryptjs ·
Vitest · Playwright. Node.js 20.9+.

**Next.js 16 differs from older versions** — check `node_modules/next/dist/docs/` before using
an API you're unsure of. Notably: middleware is now **`src/proxy.ts`** (exported `proxy`
function); `params`/`searchParams`/`cookies()` are async; `PageProps<"/route">` and
`LayoutProps<"/route">` are global types generated by `next typegen` (run by `npm run typecheck`).

## Setup, build, run

```bash
npm install
cp .env.example .env               # then fill in the values below
npm run hash-password -- 'secret'  # prints the ADMIN_PASSWORD_HASH line for .env
npm run db:migrate                 # create/upgrade the SQLite database
npm run db:seed                    # optional: two sample studies (prints their links)
npm run dev                        # http://localhost:3000
```

| Command | Purpose |
|---|---|
| `npm run dev` | Development server |
| `npm run build` / `npm run start` | Production build / serve |
| `npm run db:generate` | Generate a migration after editing `src/server/db/schema.ts` |
| `npm run db:migrate` | Apply migrations |
| `npm run lint` / `npm run typecheck` | ESLint / route typegen + `tsc --noEmit` |
| `npm test` | Vitest unit + integration tests |
| `npm run test:e2e` | Playwright end-to-end tests (starts its own dev server on :3100) |
| `docker compose up -d --build` | Build and run the production container (see README.md) |
| `npm run req:coverage` | Which requirement IDs are referenced by tests (`-- --strict` fails on missing **M**) |

Environment variables (see `.env.example`): `DATABASE_PATH`, `ADMIN_EMAIL`, `ADMIN_PASSWORD_HASH`,
`SESSION_SECRET` (≥ 32 chars), `PUBLIC_BASE_URL`.

- `ADMIN_PASSWORD_HASH` should use the `b64:<base64>` form that `npm run hash-password` prints.
  A raw bcrypt hash contains `$`, which Next.js expands inside `.env` (even quoted, and even in a
  real env var when `.env` defines the same key) and Docker Compose also interpolates. The server
  also accepts the raw hash or `\$`-escaped form.
- SQLite is used in **both** development and production — never add another database.
- e2e defaults to port 3100 / `data/e2e.db`; set `E2E_PORT=31xx` to run another suite in parallel.
- `E2E_ALL_BROWSERS=1` adds Firefox and WebKit projects (needs `npx playwright install firefox webkit`).
- CI: `.github/workflows/ci.yml` runs lint, typecheck, unit/integration, `req:coverage --strict`,
  e2e in all three browsers, and a `docker build`.
- e2e gotcha: Radix Dialog and dnd-kit's keyboard sensor attach listeners in a `setTimeout`, so
  input sent immediately after a modal opens or a card is picked up can be lost. Wait for the
  dialog to be visible / retry with `expect(...).toPass()` instead of acting instantly.
- Playwright uses the pre-installed Chromium; on a new machine run `npx playwright install chromium`.

## Conventions

- **Requirements traceability:** test names start with the requirement IDs they cover, e.g.
  `it("DONE-04: rejects ops on a completed board", ...)`. `npm run req:coverage` reports gaps.
  When you implement or change behaviour, update `docs/REQUIREMENTS.md` first if it isn't specified.
- **Business rules live in one place.** Permission checks and completion rules are pure functions
  in `src/lib/` used by both client and server. The server always enforces; the client only reflects.
- **Thin routes.** Route handlers use `route()` + `parseBody()` from `src/server/http.ts` and
  delegate to `src/server/services`. Services are synchronous, take `db: DB` as first argument,
  and throw `ServiceError` (`src/server/errors.ts`). Admin handlers call `await requireAdmin()` first.
- **Rendering:** Cache Components is **off**. Any page/layout reading the DB or session must be
  dynamic: `export const dynamic = "force-dynamic"` (already set on the `admin/(protected)` and
  `s/[slug]` layouts).
- **Server/client boundary:** files under `src/server/` start with `import "server-only"`
  (except `db/open.ts`, `db/schema.ts`, `analysis/`, which scripts/tests import). Client components
  never import from `src/server/`.
- **IDs:** server rows use `newId()`; new board groups/cards get **client-generated** nanoid ids
  sent in the `BoardOp` (validated by `IdSchema`).
- **Analysis is pure** (`src/server/analysis`) and must stay deterministic (stable tie-breaking).
- **Schema changes** go through Drizzle migrations committed under `drizzle/`; never edit an
  applied migration.
- **Never trust the client:** every board op checks the token, revision, board status, study status
  and ownership of referenced cards/groups.
- TypeScript strict mode; no `any` without a comment explaining why. Desktop-only UI (≥ 1024 px).
- Styling: Tailwind with tokens in `src/app/globals.css` (`ink`, `muted`, `line`, `canvas`,
  `accent`, `note`, …). Reuse `src/components/ui` primitives.

## Definition of done for a change

1. Behaviour matches the acceptance criteria in `docs/REQUIREMENTS.md`.
2. Tests referencing the requirement IDs exist and pass (`npm test`, and `npm run test:e2e` for
   UI flows).
3. `npm run lint` and `npm run typecheck` pass.
4. `docs/DESIGN.md`, `docs/REQUIREMENTS.md` and this file are updated if behaviour, architecture,
   layout or commands changed.
